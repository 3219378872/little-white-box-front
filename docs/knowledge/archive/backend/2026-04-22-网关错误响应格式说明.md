## 概述

本文档说明 Gateway 对外 HTTP 接口的**错误响应格式**。

当前项目运行时以 `app/gateway/gateway.go` 中注册的 `httpx.SetErrorHandlerCtx(...)` 为准：当接口返回错误时，Gateway 会统一输出 JSON，对外只暴露两个字段：

```json
{
  "code": 1001,
  "message": "用户不存在"
}
```

> 结论：**错误响应没有 `desc`，也没有 `data`。**
>
> 旧文档里出现的 `code/desc/data` 结构，不应再作为错误响应契约使用。

---

## 响应结构

### 统一格式

```json
{
  "code": 业务错误码,
  "message": "错误说明"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | int | 是 | 业务错误码，来自 `pkg/errx/codes.go` |
| `message` | string | 是 | 面向调用方的错误说明，来自 `errx.BizError.Message` |

### 设计约束

1. Gateway 不在错误响应中返回 `data`
2. Gateway 不在错误响应中返回 `desc`
3. `message` 默认可直接展示，但前端更应以 `code` 作为分支判断依据
4. 同一个 `code` 在不同接口下应保持相同语义

---

## 状态码与业务码

Gateway 的 HTTP 状态码不是随意写死的，而是由 `errx.BizError.HTTPStatus()` 推导。

常见映射如下：

| HTTP Status | 业务码示例 | 含义 |
|---|---|---|
| `400 Bad Request` | `2 ParamError`、`2004 ContentEmpty`、`4001 FileTooLarge` | 参数错误或请求内容不合法 |
| `401 Unauthorized` | `1004 TokenExpired`、`1005 TokenInvalid`、`1006 LoginRequired` | 未登录、Token 失效或无效 |
| `403 Forbidden` | `1007 PermissionDenied`、`2002 ContentForbidden`、`3007 FavoritesPrivate` | 已认证，但无权限 |
| `404 Not Found` | `4 NotFound`、`1001 UserNotFound`、`2001 ContentNotFound`、`4004 MediaNotFound` | 资源不存在 |
| `409 Conflict` | `1002 UserAlreadyExist` | 资源冲突 |
| `410 Gone` | `2006 PostAlreadyDeleted` | 资源曾存在，但已删除 |
| `429 Too Many Requests` | `5 TooManyReq` | 请求过于频繁 |
| `503 Service Unavailable` | `6 ServiceUnavailable` | 服务暂不可用 |
| `500 Internal Server Error` | `1 UnknownError`、`3 SystemError` 或其他未匹配错误 | 服务端内部错误 |

## 参数解析错误

除业务逻辑主动返回的 `BizError` 外，Gateway 还会处理 `httpx.Parse(...)` 产生的请求解析错误。

这类错误会先经 `pkg/errx/resolve_http.go` 转成：

```json
{
  "code": 2,
  "message": "具体参数错误信息"
}
```

也就是说，下列场景统一按 **`400 + ParamError`** 返回：

1. JSON 语法错误
2. 字段缺失
3. 字段类型不匹配
4. query/path/form 参数校验失败

示例：

```json
{
  "code": 2,
  "message": "field \"username\" is not set"
}
```

```json
{
  "code": 2,
  "message": "type mismatch for field \"loginType\""
}
```

## 常见错误示例

### 1. 未登录

```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json
```

```json
{
  "code": 1006,
  "message": "请先登录"
}
```

### 2. Token 失效

```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json
```

```json
{
  "code": 1004,
  "message": "Token已过期"
}
```

### 3. 用户不存在

```http
HTTP/1.1 404 Not Found
Content-Type: application/json
```

```json
{
  "code": 1001,
  "message": "用户不存在"
}
```

### 4. 帖子已删除

```http
HTTP/1.1 410 Gone
Content-Type: application/json
```

```json
{
  "code": 2006,
  "message": "帖子已删除"
}
```

### 5. 文件过大

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json
```

```json
{
  "code": 4001,
  "message": "文件过大"
}
```

## 前端联调约定

1. 错误分支统一按 `code` + `message` 解析
2. 不要假设错误响应里存在 `data`
3. 不要假设错误响应里存在 `desc`
4. 业务判断优先使用 `code`，`message` 用于展示或日志
5. 如果收到 `400 + code=2`，应优先视为请求参数或请求体格式问题

推荐伪代码：

```ts
if (!resp.ok) {
  const err = await resp.json() as { code: number; message: string }
  switch (err.code) {
    case 1006:
      // 跳登录
      break
    case 1004:
    case 1005:
      // 刷新 token / 清理登录态
      break
    default:
      // toast(err.message)
      break
  }
}
```

## 常用错误码速查

| code | message | 说明 |
|---|---|---|
| `2` | `参数错误` | 通用参数错误 |
| `3` | `系统错误` | 通用内部错误 |
| `5` | `请求过于频繁` | 限流 |
| `6` | `服务不可用` | 下游或服务不可用 |
| `1001` | `用户不存在` | 用户资源不存在 |
| `1002` | `用户已存在` | 注册冲突 |
| `1003` | `密码错误` | 登录口令错误 |
| `1004` | `Token已过期` | 认证过期 |
| `1005` | `Token无效` | 认证无效 |
| `1006` | `请先登录` | 需要登录 |
| `1007` | `权限不足` | 无访问权限 |
| `2001` | `内容不存在` | 内容资源不存在 |
| `2002` | `无权操作此内容` | 内容权限不足 |
| `2004` | `内容不能为空` | 内容校验失败 |
| `2005` | `标题不能为空` | 标题校验失败 |
| `2006` | `帖子已删除` | 资源已删除 |
| `3001` | `已点赞` | 重复点赞 |
| `3002` | `已收藏` | 重复收藏 |
| `3003` | `未点赞` | 取消点赞前置条件不满足 |

| `4001` | `文件过大` | 上传限制 |

| `4003` | `上传失败` | 上传过程失败 |
| `4004` | `媒体不存在或已删除` | 媒体资源不存在 |

## 非目标范围

本文档只定义**错误响应格式**，不定义成功响应的统一包装协议。

当前 Gateway 成功响应普遍通过 `httpx.OkJsonCtx(...)` 直接输出各接口自己的响应体，因此成功体是否包含 `code`、`data`、列表字段、对象字段，应分别以具体接口文档为准。
