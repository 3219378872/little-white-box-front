# 客户端体验与接口规格

2026-09-05 按人类批准的分层与社区 Agent 闭环方案修订。条款定义工程约束和验收条件，不规定组件、
字段布局或传输实现。现有路由、生成契约和机制由设计承接；既有编号、能力、安全、兼容和指标保留。

## 访问与身份

- `FX-001`：匿名用户可浏览推荐、搜索、已发布帖子和公开资料并进入登录/注册；读取故障不伪装空结果。
- `FX-002`：创作、个人中心、关注流、私信和 Assistant 需要认证；受保护入口引导登录，认证后不会停留
  在无效登录入口。客户端守卫不替代服务端鉴权。
- `FX-010`：启动可恢复身份；明确失效的凭证被清理，其他错误保持身份及可恢复状态。旧账号的响应不得
  覆盖或清理新账号。

## 内容发现

- `FX-020`：推荐支持首屏、刷新和游标分页；同一请求链保留请求、位置、来源、模型与实验归因，并按
  精确帖子标识去重。
- `FX-021`：关注流只对认证用户加载，使用服务端游标；空关注流不以推荐内容冒充。
- `FX-022`：搜索区分综合、用户和标签，并明确区分待输入、加载、成功、空态、部分降级及失败；帖子
  搜索不可用不能显示为无匹配项。

## 内容、媒体与互动

- `FX-030`：帖子写操作遵循幂等和版本检查；冲突或结果不确定时保留输入，不覆盖并发修改或用新标识
  重复提交旧命令。
- `FX-031`：详情支持评论分页/排序、点赞和收藏，资料支持权限内的帖子与收藏列表；失败互动回滚本地
  乐观状态，不暴露不可访问内容。
- `FX-032`：接受标题 1～120 字符、正文 1～20,000 字符、最多 9 张图片与 10 个标签；图片仅支持
  JPEG/PNG/WebP、单图不超过 10 MiB。任一图片上传失败不得继续发布。

## 一对一私信

- `FX-040`：认证用户可分页读会话/历史并发送文本或已上传媒体；文本 1～1,000 字符，发送标识最长
  128 字符；同一失败命令重试复用标识。
- `FX-041`：已读只影响本人当前会话；列表、线程和未读徽标在成功后收敛，局部故障不伪造零未读。

## Assistant 基础约束

- `FX-050`：每个认证用户拥有消息页固定的 Agent 虚拟线程，不作为独立主导航或普通机器人私信。
  旧入口保持可达；输入 1～2,000 字符，每条命令具有稳定标识。
- `FX-051`：可信来源只来自服务端验证记录，不从模型正文提取 ID 或链接建立信任；站内资料可进入
  对应帖子，站外资料明确区分。普通对话不因没有来源卡而失败。
- `FX-052`：移动和桌面均可从消息页进入同一助手线程、记忆和 Watch；身份守卫及信息层级一致。
- `FX-053`：首次用户任务前展示当前能力分组、数据边界、删除确认、记忆、Watch 和预算，取得显式
  授权；取消授权流程不发送任务。
- `FX-054`：服务端拒绝 Agent 授权时可重新授权并重试原消息，不伪造已执行结果。
- `FX-055`：支持图片附件，遵循发布图片的类型与大小限制；上传成功后可预览、移除并随当前消息提交。
- `FX-056`：工具过程展示人可读进度，结束后可收敛为摘要；高风险确认清楚展示操作对象与影响。
- `FX-057`：确认一次有效；拒绝、过期、冲突和提交失败明确呈现，不重复确认或阻断后续事件。
- `FX-058`：忙碌时仍可发送消息；安全阶段按服务端结果转向/补充，不安全阶段有界排队，最大 32 条。
  只有显式 Stop 硬取消，断线不取消任务。
- `FX-059`：未知事件不导致整条响应终止；流式消费遵循服务端顺序和终止语义，不伪造成功。
- `FX-080`：授权版本落后时须重新披露并确认升级；升级前不发起用户任务，记忆/Watch 保持只读可恢复提示。
- `FX-081`：用户可查看 MEMORY/USER 条目、版本和容量，并新增、替换、删除、撤销；失败不显示为空成功，
  不展示模型推测形成的隐藏画像。
- `FX-082`：用户可列出、创建、启停和删除本人 Watch；只提交当前支持的四种规则条件，不提供独立命中收件箱。
- `FX-083`：Watch 主动消息进入助手线程并计入合并未读，不作为普通私信或通知中心。
- `FX-084`：来源卡与正文引用关联清楚，来源失效明确标注；卡片标题、摘要或模型数字本身不构成可信依据。
- `FX-085`：记忆变更提示不计未读，提供撤销；失败独立呈现，不阻塞其他消息。
- `FX-086`：已授权用户可从帖子发起盯作者/盯修订；未授权引导到助手完成授权。
- `FX-087`：适用的推荐来源保留不喜欢/不感兴趣反馈，失败不回写成功态。
- `FX-088`：会话与助手线程状态共同构成消息能力；挂载期间线程状态最迟每 30 秒主动刷新一次，
  成功标记已读后收敛，失败不伪造零未读。
- `FX-089`：任务被持久接受后立即进入异步展示，不等待模型完成；区分开始、转向、补充和排队结果。
- `FX-090`：重连恢复已提交事件；不同模型尝试隔离，被替代尝试的文本不得混入获胜回答。断流保留
  有效部分并显示恢复状态，不伪造完成。
- `FX-091`：显式 Stop 后不继续追加该 run 的迟到输出。
- `FX-092`：没有新会话入口，永久前台对话由服务端维护；冷对话拼接不清空历史。清除历史不删除
  MEMORY/USER 或 Watch。
- `FX-093`：进入助手线程标记本人已读；失败可独立重试，Watch 计未读，记忆变更不计未读。
- `FX-094`：普通回答可延迟揭示已接收内容；终止、取消或替换后必须对齐协议提交正文。历史和恢复前缀
  不重新打字，揭示缓冲不持久化；禁用动画时直接显示。

## 复杂需求与来源卡

- `FX-095`：结构化问题支持单选、多选、文字补充、未知、无偏好、跳过及先搜索；不预选未确认偏好。
  提交失败保留输入，同一命令重试不重复接受。
- `FX-096`：待答问题可在刷新或断线后恢复，区分待答、已答、过期、取消和转向。等待沿用 30 分钟无活动
  与 6 小时总时限；迟答须由用户显式继续新任务，不重开旧任务，不把等待当作答案。
- `FX-097`：一篇帖子或网页一张来源卡，默认展示相关原文摘录，可展开及访问原文；站内/站外、正文/评论
  与搜索摘录可区分。缺少元数据或图片不编造，不加载任意外部预览图片。
- `FX-098`：检索型综合回答在结构化校验后完整发布，过程中展示进度；正文、逐项引用和卡片从同一持久
  快照恢复。普通闲聊继续流式输出，不以卡片替代自然语言解答。
- `FX-099`：每处引用可定位对应来源；模型自由文本链接不绕过验证。源失效时隐藏不可展示摘录并标注
  受影响引用，原文打开失败可恢复，移动端与桌面端均可核验。

## 行为反馈与验证

- `FX-060`：客户端只上报自身拥有的曝光、点击、停留、浏览、播放、分享、隐藏和不喜欢；权威赞评关等
  业务动作不重复上报。
- `FX-061`：推荐曝光要求至少 50% 可见并连续 1 秒，同一请求与帖子只记录一次；反馈保留完整归因上下文。
- `FX-062`：待发送反馈可靠保留，单批最多 100 条并按身份/会话隔离；只移除已接受或永久拒绝项，临时
  失败有界重试，分析故障不阻断用户主操作。
- `FX-070`：Mock 与真实网关使用相同页面、状态、repository 和错误分支；覆盖关键成功与失败契约。
  Mock 不能替代真实鉴权、代理、权限、流式恢复及线上质量证据。

每个条款必须有设计映射、实现状态和带版本证据。布局证据、确定性协议测试、人类质量评审和真实环境
观测分别报告，不相互替代。
