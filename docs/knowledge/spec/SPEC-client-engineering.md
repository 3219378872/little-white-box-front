# 客户端工程规格

2026-09-05 按已批准实施方案重新分层。规格定义工程约束、指标和验收条件；框架、组件库、目录、
生成命令和内部状态机制进入设计，不以本次整理更换当前技术栈。

## 工程约束

- `FQ-001`：状态、导航、业务命令和传输适配有明确所有者；依赖方向可检查，主要状态转换可独立测试，
  页面不能绕过统一权限、错误和业务命令处理路径。
- `FQ-002`：客户端契约与当前后端定义可重复同步；生成物不承载手写业务修复。生成检查不得产生未解释
  的接口差异，实体标识跨序列化、路由、比较和回传保持精确，不因平台数值表示而改变。
- `FQ-003`：错误按 HTTP 与结构化业务结果分类；未知或格式错误响应进入失败态。只有明确的凭证拒绝
  才清理对应身份，临时网络故障及其他业务错误不得误清会话。
- `FQ-004`：共享组件、颜色、排版、反馈和辅助功能语义一致；新界面复用当前设计系统，不建立独立主题。
  图标操作具有可访问名称和提示，文本不溢出或遮挡相邻内容。
- `FQ-005`：亮暗主题及移动/桌面场景都可完成核心流程；信息层级不因平台改变。内容宽度受约束，
  控件适应长文本、触摸、键盘和禁用动画设置，不以 Web 证据替代原生平台验证。
- `FQ-006`：异步状态区分首次加载、刷新、分页、空态、局部失败和终态；陈旧或旧账号结果不得污染当前
  页面。失败重试不重复权威写入；同一失败命令保持标识，参数变化必须形成新命令。
- `FQ-007`：变更通过相应静态、单元、Widget、真实接口和浏览器验证；测试使用与应用一致的全局环境。
  证据记录版本、实际命令、结果及未覆盖边界，截图证明布局而不代替服务端正确性测试。
- `FQ-008`：行为变更可沿稳定条款追溯到设计、实现与证据；ID、层间引用、条款覆盖、双向证据和本地
  链接可机器校验。历史计划不作为当前约束，结构检查通过不等于实现或产品质量通过。
