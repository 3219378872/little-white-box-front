# Assistant 问答与来源摘录卡片

## 承接范围

本局部设计承接人类批准的社区 Agent 闭环，不替代整体仍为 baseline 的 Flutter 设计。Riverpod、
GoRouter、Forui、SDK 双副本、generation 与流式尝试隔离继续沿用；本次规格重新分层不更换技术栈。
前端只渲染后端提交的展示数据，不能从模型正文推断来源或让问答越过授权和删除确认。

## 数据与命令

消息发送声明 clientProtocolVersion=2。新增 questionRequest 和 answerPresentation 领域 DTO，REST
和 SSE 共用解析；实体 ID 使用现有精确整数适配。新增问题回答命令和显式超期继续命令，原消息、
记忆、Watch、授权及旧事件仍兼容。网关契约经同步脚本显式指定后端工作树，再生成 SDK 的来源与副本。

待答问题绑定 run/question/call/message，逐题提交选项 ID、文字和 disposition。同一问答命令按完整
参数指纹复用 requestId，失败保留输入，参数变化换新标识。提交成功更新对应问题并恢复事件订阅。
超期继续通过 questionContext 创建新 run，不重开旧任务；当前有其他活跃任务时不自动替换它。

## 问答界面

一批问题是一件平铺的框定工具，不再给每题嵌套卡片。单选使用 FRadio、多选使用 FCheckbox，所有选项
初始不选。未知、无偏好和跳过与实际选项互斥；文字补充可单独构成答案。“先搜索”仅把未回答项明确
记为跳过。提交失败不清选择，历史中的已答和转向项只读；过期/取消项可显式继续。

问题的可见文本与 provider 的工具调用分开，UI 从 questionRequest 恢复控件和已提交答案，不从
普通 Markdown 解析问题。等待期间输入框和 Stop 保留；断线后带游标恢复，等待不显示持续生成动画。
已回答的问题默认折叠为真实选择与文字的只读摘要，可展开详情；不会在完成回答后保留大块禁用表单。

## 正文与来源卡

检索型回答收到 answer_committed 后一次渲染 blocks 和 sources。正文无外框，来源卡在正文后单列平铺；
每处引用按钮定位并突出对应卡片。同一来源多次被引用只显示一张卡。推导和个人体验有独立类别标识，
资料不足明确说明，普通对话继续复用既有流式揭示组件。

卡片使用 Forui 与现有主题，标题最多两行、摘录默认三行，展开显示所有已取得片段；默认不展示内部
handle。可选缩略图为 72px 方形，仅加载同源 /xbh-media/ 地址；正文内 Markdown 图片不发起请求。
网页首版文字卡，显示站点和搜索摘录，不额外抓取预览或声称取得全文。未知作者、时间和图片直接省略。

“查看原文”与摘录展开分开；帖子通过真实标识进入详情，外部 HTTP/HTTPS 通过 url_launcher 打开。
模型自由文本链接不可点击，只有结构化引用与来源入口具有导航行为。原文打不开显示可恢复错误；
来源失效隐藏摘录并标记受影响引用。保留适用的帖子推荐反馈。

## 恢复与验证

问答按问题 ID 更新，最终回答按 run/message 身份合并；不会因历史分页或 SSE 重放重复插入，也不会
把重新发布的回答放回旧问题之前。Stop、旧连接、旧账号和旧流实例继续受原有状态边界约束。
Mock 在同一 transport 后模拟问答与快照；其内容只验证协议和布局，不作为真实检索质量证据。

验收包括未预选、跳过/文字补充、失败重试、历史恢复、重复事件、引用定位、失效来源、外链失败、
长文本和窄屏、亮暗主题、禁用动画及账号切换。实际命令、浏览器截图和未验证边界记入证据层。
