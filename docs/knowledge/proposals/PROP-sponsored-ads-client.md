## 背景与现状

- 客户端没有广告、广告主或审核界面，也没有角色概念：`AuthState` 与 JWT 解码只读取用户标识，路由守卫
  只区分登录页与公开页。
- [意图](../intent/INT-content-community-client.md)把管理后台列为非目标；
  [工程规格](../spec/SPEC-client-engineering.md)的 `FQ-009` 要求不新增游戏库、商城等业务。
- 推荐流解析要求每个条目都是完整帖子，缺字段时整页失败（`lib/features/feed/data/feed_repository.dart`
  的 `_parsePost`）。顶层只读取 `items`、`hasMore`、`nextCursor`、`requestId`。
- 行为上报固定 `targetType: 'post'`，持久化的曝光去重键不含目标类型
  （`lib/features/behavior/application/behavior_tracker.dart`）。
- Mock 推荐流在 `lib/mock/mock_discovery.dart` 中生成；`MockHttpClient` 与真实网关共用同一套 repository 路径。
- 根仓反代 CSP 的 `img-src` 只放行同源、`data:`、`blob:` 与 picsum，广告素材必须经同源 `/xbh-media/` 提供。

## 人类已决定（2026-10-01，当前对话）

- 做完整投放闭环：推荐流广告卡片、广告主控制台与审核工作台都做 Flutter 页面。
- 匿名用户的广告频控按会话计数；已过审广告被编辑后，新版本审核期间继续展示上一过审版本。

## 建议的意图变更（INT-content-community-client）

- 目标结果新增：
  - 用户能在推荐流中识别广告及其广告主，了解为什么看到这条广告，并可以隐藏或举报。
  - 广告主能管理资质与广告、查看审核结果并申诉。
  - 审核人员能在授权范围内领取并处理审核任务。
- 非目标中的「管理后台」限定为社区内容的管理后台；广告主控制台与广告审核工作台不在此列。

## 建议的规格条款

体验（[体验规格](../spec/SPEC-client-experience.md)）：

- `FX-100`：服务端返回广告槽位时，推荐流按槽位位置把广告卡片展示在自然内容之间。卡片显示「广告」标识
  与广告主名称；标识对辅助技术可读，且不只靠颜色区分。
- `FX-101`：广告卡片提供「为什么看到这条广告」，展示服务端返回的主要参数，并提供隐藏与举报入口；
  隐藏后，当前列表立即移除该广告。
- `FX-102`：打开落地页前显示目标域名，以外部方式打开服务端返回的过审落地页，不在应用内嵌入第三方页面。
- `FX-103`：单个广告槽位格式错误时只丢弃该槽位，不让自然内容页面失败。广告不参与帖子去重，帖子位置
  只按自然内容计数。
- `FX-104`：广告曝光沿用 `FX-061` 的定义（至少 50% 可见并连续 1 秒），以广告目标类型上报，去重键
  包含目标类型；点击、隐藏与举报保留请求链归因。
- `FX-105`：请求推荐流时声明支持广告槽位；Mock 模式提供同形的广告数据，并覆盖成功与失败分支（`FX-070`）。
- `FX-110`：广告主控制台支持申请广告主、提交资质、创建与编辑广告、上传素材、送审、查看状态与政策码原因、
  发起申诉。编辑已过审广告时，提示审核期间会继续投放上一过审版本。
- `FX-111`：审核工作台按授权队列领取任务，展示快照、机审证据与政策定义；提交结论时必须选择政策码；
  支持续期与放弃。持有过期或任务作废时明确提示，且不重复提交。
- `FX-112`：控制台与工作台入口只对具备相应资格或角色的用户显示。客户端守卫不替代服务端鉴权（`FX-002`），
  服务端拒绝后按无权限处理。
- `FX-113`：质检复审与申诉任务在工作台中与首次审核区分展示，并显示原结论。

工程（工程规格）：

- 修订 `FQ-009`：允许新增后端 `SPEC-sponsored-ads` 范围内的广告投放、广告主控制台与审核工作台界面；
  仍不新增游戏库、商城等其他业务。
- `FQ-010`：广告卡片、控制台与工作台复用现有设计系统，覆盖亮暗主题与移动、桌面场景（`FQ-004`、`FQ-005`）。
- `FQ-011`：新增接口经 SDK 同步（`FQ-002`）；广告槽位的容错解析与帖子条目的严格解析相互独立（`FQ-003`）。

## 影响

- 推荐流：`FeedEntry` 拆成自然内容与广告两类，repository、notifier 与列表渲染相应调整，新增广告卡片组件。
- 行为上报：tracker 支持目标类型参数；持久化的曝光去重键改为包含目标类型的格式。
- 新增功能模块与路由：广告主控制台、审核工作台。入口位置见下方待决事项。
- Mock：新增广告槽位、广告主与审核数据，契约测试同步更新。
- 证据：Widget 测试、Mock 浏览器截图与真实联调分别记录 scope，不互相替代。

## 待人类决定

- 控制台与工作台的入口：建议放在个人页与桌面侧栏，不增加主导航第六项。
- 审核工作台在移动端是否要求完整可用：`FQ-005` 目前要求移动端和桌面端都能完成核心流程，建议保持。
- 广告卡片视觉：与帖子卡片同构、只加标识，还是使用独立样式。
