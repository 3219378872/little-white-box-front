## 接口 1：用户的帖子列表

### 请求

```
GET /api/v1/users/{userId}/posts?page={int}&pageSize={int}&sortBy={int}
```

| 字段 | 位置 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|---|
| `userId` | path | int64 | 是 | — | 目标用户 ID |
| `page` | query | int | 是 | — | 从 1 开始 |
| `pageSize` | query | int | 是 | — | 建议 max=50 |
| `sortBy` | query | int | 否 | 1 | 1=最新 / 2=热门 |

### 响应

复用现有 `GetPostListResp`：
```json
{
  "code": 0,
  "desc": "ok",
  "data": {
    "list": [PostItem, ...],
    "total": 123,
    "page": 1,
    "pageSize": 20
  }
}
```

`PostItem` 字段与 `GetPostListResp.list` 一致，**每条帖子的 `isLiked` / `isFavorited` 字段按当前请求者状态填充**（未登录请求者全部返回 false）。

### 权限

**公开**。登录与否都能访问（看别人主页是公开功能）。

### 业务规则

1. 只返回 `status = 1`（已发布）的帖子
2. 按 `sortBy` 排序（最新 = `created_at DESC`；热门 = 业务定义）
3. 软删除的帖子不返回
4. 目标 userId 不存在时返回 `{code: 非 0, desc: "user not found"}`

### go-zero .api 定义建议

```go
@server(
    group: user
)
service gateway {
    @doc "获取用户发布的帖子列表"
    @handler getUserPosts
    get /api/v1/users/:userId/posts (GetUserPostsReq) returns (GetPostListResp)
}

type GetUserPostsReq {
    UserId   int64 `path:"userId"`
    Page     int   `form:"page"`
    PageSize int   `form:"pageSize"`
    SortBy   int   `form:"sortBy,optional,default=1"`
}
```

## 接口 2：用户的收藏列表

### 请求

```
GET /api/v1/users/{userId}/favorites?page={int}&pageSize={int}
```

| 字段 | 位置 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|---|
| `userId` | path | int64 | 是 | — | 目标用户 ID |
| `page` | query | int | 是 | — | 从 1 开始 |
| `pageSize` | query | int | 是 | — | 建议 max=50 |

### 响应

复用 `GetPostListResp`（与接口 1 相同）。

### 权限

**基于用户级开关 `favorites_visibility` 决定**（见下方"数据库变更"）：

| 场景 | 规则 |
|---|---|
| 请求者 = 目标用户（本人访问自己的收藏） | 始终允许 |
| 请求者 ≠ 目标用户 且目标用户 `public` | 允许 |
| 请求者 ≠ 目标用户 且目标用户 `private` | **403 Forbidden**（或 `{code: 非 0, desc: "favorites are private"}`） |
| 未登录访客 且目标用户 `public` | 允许 |
| 未登录访客 且目标用户 `private` | **403 Forbidden** |

**注意**：`favoritesVisible` 字段必须在 `GetUserResp` 中无条件返回（登录与否都返回），这样前端才能在 `/profile` 页面根据此字段决定是否显示"收藏"Tab，不必撞 403 才知情。接口 2 的 403 是后端兜底防御，前端正常路径走不到。

### 业务规则

1. 按"收藏时间倒序"返回（`favorite.created_at DESC`）
2. 被收藏的原帖**已被软删除时，服务端过滤掉不返回**（前端不处理幽灵条目）
3. 响应里每条帖子的 `isLiked` / `isFavorited` 字段按请求者状态填（一般来说 `isFavorited` 会是 true，因为是查收藏列表；但请求者是别人时按请求者实际的收藏状态填）

### go-zero .api 定义建议

```go
@server(
    group: user
    middleware: OptionalAuth  // 可登录可不登录，但要拿到 tokenUserId 做权限判断
)
service gateway {
    @doc "获取用户的收藏帖子列表"
    @handler getUserFavorites
    get /api/v1/users/:userId/favorites (GetUserFavoritesReq) returns (GetPostListResp)
}

type GetUserFavoritesReq {
    UserId   int64 `path:"userId"`
    Page     int   `form:"page"`
    PageSize int   `form:"pageSize"`
}
```

## 接口 3：图片上传协议变更

### 当前状态

SDK 当前生成的 `uploadImage`：
```
POST /api/v1/media/image
Content-Type: application/json
Body: {"file": [1, 2, 3, ...]}   // 图片字节的 int 数组
```

**问题**：JSON 数组编码导致一张 2MB 图变成 ~10MB 的 JSON 字符串，大概率被 body size limit 挡掉或传输超时。

### 新协议

```
POST /api/v1/media/image
Content-Type: multipart/form-data; boundary=...
Authorization: Bearer <accessToken>

form fields:
  file: <binary image data>
```

### 请求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | form-data file | 是 | 图片二进制，字段名固定为 `file` |

### 响应

**保持与现有一致**（前端 `decodeData` 只读 `url` 字段）：
```json
{
  "code": 0,
  "desc": "ok",
  "data": {
    "url": "https://cdn.example.com/images/xxx.jpg"
  }
}
```

### 服务端要求

1. **单文件大小上限 10 MB**（前端不做压缩，全部原样上送）
2. **Content-Type 校验**：只接受 `image/jpeg`、`image/png`、`image/webp`；其它类型返回错误
3. **图片压缩/缩放在服务端完成**（前端不负责；存储的是后端处理后的版本）
4. **认证要求**：必须带 `Authorization: Bearer <token>` header；未登录返回 401
5. **并发**：前端会并行上传（`Future.wait`），一次最多 9 张图，服务端 handler 需可重入
6. **幂等性**：不做要求（每次上传都返回新 URL，前端不会重试同一张图）

### 旧协议的兼容性

**建议直接废弃 JSON 版本**。前端切换后不会再调 JSON 路径，保留旧代码没意义。

### go-zero .api 定义建议

go-zero 对 multipart 支持有限，可能需要手写 handler 或用 `httpx.Parse` 之外的方式。参考实现思路：

```go
// 在 handler 里手动处理
func uploadImageHandler(ctx *svc.ServiceContext) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        // 1. r.ParseMultipartForm(10 << 20)  // 10 MB
        // 2. file, header, err := r.FormFile("file")
        // 3. 校验 Content-Type 是否在白名单
        // 4. 读取字节、压缩、上传到存储（OSS/S3/本地）
        // 5. 返回 {code: 0, data: {url: "..."}}
    }
}
```

**注意**：如果 `.api` 文件定义路由是 POST + JSON body 自动生成的 handler，可能需要手动在 generated handler 里改，或者把这个路由从 `.api` 中移除、改在 route 注册时手动挂 handler。具体方式你最熟悉。

## 数据库变更：`user.favorites_visibility`

### 新增字段

| 列名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `favorites_visibility` | `tinyint` | `1` | 收藏列表可见性：`1`=公开，`2`=私密 |

### Migration SQL（示意）

```sql
ALTER TABLE `user`
  ADD COLUMN `favorites_visibility` TINYINT NOT NULL DEFAULT 1 COMMENT '收藏可见性：1=公开，2=私密';
```

### 默认值

**所有新用户默认 `1`（公开）**。老用户由 migration 的 DEFAULT 1 自动回填。

### 在 `GetUserResp` 中暴露

前端 `_ProfileContent` 需要根据目标用户的 `favoritesVisible` 决定是否显示"我的收藏"Tab（他人视角下）。**该字段必须无条件返回**（登录/未登录都返回），这样前端可以在不触发 403 的情况下就决定 UI 裁剪。

**请在 `GetUserResp` 中新增字段（已敲定为 bool 形式）**：

```go
type GetUserResp {
    // ...现有字段...
    FavoritesVisible bool `json:"favoritesVisible"`  // true = 公开，false = 私密
}
```

**命名约定**：
- 数据库列名：`favorites_visibility`（数据库风格，`tinyint`）
- JSON/API 字段名：`favoritesVisible`（`bool`）
- Go struct 字段：`FavoritesVisible`

**映射规则**：
- DB `1` → API `true`
- DB `2` → API `false`

这是**唯一需要改 SDK 生成入口的字段**，通过后端 `.api` 文件更新、重新生成 SDK 完成。

## 接口 4（可选）：`/api/v1/me`

**本次不依赖**。列出仅作为下次迭代建议。

### 动机

当前方案（Y2）解 JWT 只能拿到 `userId`，冷启动时头像/昵称要等进入 `/profile` 再调 `/users/:userId` 才显示，顶栏头像有闪现。加这个接口后 `AuthState` 可一次性存全用户信息。

### 请求

```
GET /api/v1/me
Authorization: Bearer <accessToken>
```

### 响应

复用现有 `GetUserResp`（等同于 `GET /api/v1/users/{当前 userId}` 的效果）。

### 权限

必须登录。未登录返回 401。
